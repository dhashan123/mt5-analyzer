What a conversion actually involves

Sierra Chart studies are ACSIL C++ running inside a chartbook. Pine Script is a vectorised bar language. NinjaScript is C# on a different event model. MQL4/MQL5 is an EA framework with its own execution and history model. The same words — “bar close”, “stop”, “session”, “volume” — mean different things in each.

The failures are rarely syntax errors. They are:

  • Bar-close assumptions. A study calculated on the close of a bar cannot be reproduced on a platform that evaluates intrabar by default, unless the condition is pinned.
  • Intrabar stop handling. Whether a stop fills at the level, at the next tick, or at the bar open is a modelling choice with a real P&L difference.
  • Session and exchange time. Sierra Chart’s session settings, daylight saving and exchange time are not the same as the broker’s server time.
  • Volume and delta. Ask/bid volume, cumulative delta and volume-at-price are built from different data on different platforms. Some cannot be reproduced exactly.
  • Scaling and auto-fit. A chart that looks identical can be plotting a different scale, which changes every visual comparison.

The first deliverable is a behaviour map

Before writing code, I produce a numbered list: every input, every calculation, every alert, and every place where the target platform does not have the same primitive. Each item is marked exact, approximate, or not reproducible. You see that list before the build, so there is no surprise at handover.

If all you have is a .Cht chartbook, that is a configuration — not the study source. I can read the configuration and reconstruct the visible logic, but the first step is still the map, and the quote depends on what the map finds.
